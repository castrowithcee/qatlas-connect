# Amazon S3

Group `s3`, the S3 API for general purpose buckets. S3 is regional: every tool takes an optional `region`, which may be
left out when the connection lists exactly one region and otherwise must name an allowed one. Every permission a tool
needs is listed in [Set up AWS](setup.md#s3). The tools work on the buckets of the bound account; they do not touch
objects.

## Tools

Reads need no confirmation. Every other tool needs confirmation. None is listed-only. Every tool takes the bucket as
`bucket`, except `bucket.list`. A result carries `region`, the region that was called.

`bucket.list` takes `prefix`, `bucket_region`, `page_size` (1 to 10000), and `cursor`, and returns `buckets`, `owner`,
`next_cursor`, and `has_more`. A configuration that does not exist (default encryption, tags, public access block,
lifecycle, CORS, website, replication, ownership controls) answers not-found. The confirmation is the one every tool with an effect has: the request names the tool, so the
description of the tool, not the confirmation prompt, says which bucket and region it changes.

## Bucket names and addresses

`bucket` must be the name of a general purpose bucket: 3 to 63 characters of lower case letters, digits, hyphens, and
dots, beginning and ending with a letter or digit. A name with upper case letters or underscores is accepted for a
bucket that exists, since old buckets have them, but never for `bucket.create`. IP addresses, access points, Express
One Zone and Multi-Region Access Point names, and reserved prefixes and suffixes are refused before any request. A name
that is one lower case DNS label goes in the host (`<bucket>.s3.<region>.amazonaws.com`), every other valid name in the
path of the regional host. A bucket in another region answers an error that names the region of
`x-amz-bucket-region`; call again with it. No redirect is followed.

## Expected owner

Every tool except `bucket.create` and `bucket.list` sends the account the connection is bound to as the expected
bucket owner, so a bucket of another account is refused by S3 and never read or changed. It is not an argument, under
no spelling. `CreateBucket` has no such header; the bucket does not exist yet, and the account check of the connection
covers it. A bucket name is global: a name that another account owns answers `BucketAlreadyExists`, one the bound
account owns answers `BucketAlreadyOwnedByYou`, both as a conflict.

## Creating and deleting a bucket

`bucket.create` makes a bucket in the region of the call with ACLs turned off: `object_ownership` offers only
`BucketOwnerEnforced`, the default, since `ObjectWriter` and `BucketOwnerPreferred` turn ACLs on. The
`create_bucket_configuration.location_constraint` must be the region of the call, which the connection must allow,
and is refused before any request otherwise; in `us-east-1` the model does not list the region, so the constraint is
left out and a given one is refused. In every other region the constraint is required. `tags` may be given with the
configuration. Not offered: all ACL and grant arguments, Object Lock (it cannot be turned off again), the account
regional namespace, and directory buckets.

S3 charges for the data a bucket holds and for requests to it. An empty bucket holds no data, but the name is yours
only while the bucket exists.

`bucket.delete` removes an empty bucket. A bucket with objects, versions, or delete markers answers a conflict
(`BucketNotEmpty`) and stays. The name then becomes free for anyone.

## Versioning, encryption, and tags

- `versioning.put` sets `status` to `Enabled` or `Suspended`. Versioning cannot be turned off again, only suspended;
  existing versions stay and are billed as storage. MFA delete and the MFA header are not offered.
- `encryption.put` replaces the whole default encryption: `rules`, each with `apply_server_side_encryption_by_default`
  (`sse_algorithm` `AES256`, `aws:kms`, or `aws:kms:dsse`, and `kms_master_key_id` for the KMS kinds),
  `bucket_key_enabled`, and `blocked_encryption_types`. Repeat what is to stay. Customer-provided keys (SSE-C) are not
  offered, and the algorithms of other AWS services are not accepted. `encryption.delete` removes the configuration;
  S3 then encrypts new objects with SSE-S3 as it does for every bucket.
- `tagging.put` replaces all tags (`tag_set`, each with `key` and `value`); `tagging.delete` removes them. The tool
  caps a request at 100 tags with keys up to 256 and values up to 512 characters; S3 enforces its own, lower limits.
  Tags are written by the users of the account and are untrusted data.

### KMS keys

The model marks the KMS key ID sensitive, but it is an identifier and not a secret, so the table releases it: the
result of `encryption.get` shows it, and `encryption.put` takes it. Every `kms_master_key_id` of a rule must be the ARN
of a key (`arn:aws:kms:<region>:<account>:key/<id>`) or of an alias (`arn:aws:kms:<region>:<account>:alias/<name>`)
of the bound account in an allowed region of the connection. A bare key ID or alias name carries no account and is
refused, as is an ARN of another account, region, partition, or resource type. Every rule is judged before any request.
The policy of the key must still allow the use.

## Public access block

`public-access-block.put` sets `block_public_acls`, `ignore_public_acls`, `block_public_policy`, and
`restrict_public_buckets`. It keeps or tightens the block and never loosens it. Before the change the tool reads the
current block with `GetPublicAccessBlock` of the same bucket and region, with the bound account as the expected owner:

- A bucket without a block (`NoSuchPublicAccessBlockConfiguration`) counts as all four settings off.
- A setting that is on and would be set to `false`, or left out (a setting left out of the request counts as `false`),
  refuses the call, and nothing is changed. A setting that stays, or goes from off to on, is allowed.
- Any other failure to read refuses the call: access denied, a timeout, a missing bucket, a server error, and an answer
  that is not a configuration, such as one without any of the four settings or with a value that is no boolean. A
  setting missing from a configuration that has others counts as off.

The read is part of the tool and cannot be skipped by an argument. The block of the account applies as well and is
neither read nor changed. Another writer can change the block between the read and the change; this cannot be
excluded.

## Lifecycle and CORS

`lifecycle.put` replaces all rules of the bucket, so a rule that is not given is removed. A rule with `expiration`
deletes objects after `days` or on `date`, and a rule with `noncurrent_version_expiration` deletes noncurrent versions;
deleted data is gone unless versioning keeps it. A rule acts only on what its `filter` selects (`prefix`, `tag`,
object sizes, or `and` of them). A rule without a filter, or with an empty prefix, covers the whole bucket. A
rule of the old form is limited by a rule-level `prefix` instead of a filter. `lifecycle.get` shows that `prefix` on the
rule, and it limits the rule like a filter prefix; `lifecycle.put` does not offer it, so when a rule read with a
rule-level prefix is written back, `filter.prefix` must carry the same value, or the rule covers the whole bucket.
`transition_default_minimum_object_size` is a request argument and a result field. `lifecycle.delete` removes all rules.

`cors.put` replaces all rules; `cors.delete` removes them. An `allowed_origins` entry of `*` lets a browser on any website
read the responses of the bucket; CORS is no permission, and the bucket policy, ACLs, and the public access block still
decide who may use it. Both puts carry the SHA-256 checksum of the body that S3 requires; it is never an argument. A
document S3 rejects (`MalformedXML`) is an error, and the put is not repeated. The tools cap the lists and strings of the
rules above the limits of S3; S3 enforces its own.

## Reading the other configuration

`acl.get`, `website.get`, `logging.get`, `notification.get`, `replication.get`, `ownership.get`, `accelerate.get`, and
`request-payment.get` only read. `acl.get` returns the owner and the grants, each with the grantee (`type`, `id`,
`display_name`, `email_address`, `uri`) and the permission. The logging, notification, and replication configuration can
name buckets, topics, queues, functions, and accounts other than the bound one; they are returned unchanged as
untrusted data, and a reader neither follows a target nor fetches a URL
from it. That a bucket sends events to EventBridge is not shown, because the setting is an empty element that a result
does not carry. `ownership.get` has no write tool.

## Never tools

| AWS operation | Why |
| --- | --- |
| `DeletePublicAccessBlock` | Removing the block is a loosening; the block is only kept or tightened. |
| `PutBucketAcl`, `PutObjectAcl` | ACLs can open a bucket or object to the public and bypass the checks above. |
| `PutBucketWebsite` | A website endpoint publishes objects over plain HTTP. |
| `PutBucketLogging` | Access logs can be delivered to a bucket of another account, and nothing checks the target. |
| `PutBucketNotificationConfiguration` | Events can go to topics, queues, and functions of other accounts, and nothing checks the target. |
| `PutBucketReplication`, `DeleteBucketReplication` | Objects can be copied to a bucket of another account, and nothing checks the target. |

No tool writes an ACL, a grant, a website, logging, notifications, or replication, and none creates or returns a
presigned URL.
Bucket policies, objects, Object Lock, and writing the payment model, acceleration, and ownership are not tools.

## Limits

- No live test has been run against S3. The behaviour of `SlowDown`, request costs, and the exact error codes of the
  write operations is documented by AWS only and has not been verified; a code the table does not know is reported as
  an unknown code.
- Everything S3 returns, including bucket names and tags, is untrusted data.
